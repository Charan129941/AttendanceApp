# iOS Setup & Build Instructions
**Attendance Secure System**

This guide explains how to build, test, and install the iOS version of the Attendance Secure System. The project has been fully updated with a native Swift BLE module that perfectly mirrors the Android behavior, using the exact same 12-byte payload architecture.

## 1. Files Added & Modified
- **`ios/AttendanceApp/BLEBroadcasterModule.swift`**: Completely rewritten to support the 12-byte binary payload used by Android. It uses a 16-byte custom Service UUID prefix workaround to bypass Apple's strict background Manufacturer Data restrictions.
- **`ios/AttendanceApp/BLEBroadcasterBridge.m`**: Objective-C bridging file for React Native compatibility.
- **`ios/AttendanceApp/Info.plist`**: Added `NSBluetoothAlwaysUsageDescription` and `NSBluetoothPeripheralUsageDescription` for privacy permissions.
- **`android/app/src/main/java/com/attendanceapp/BLEBroadcasterModule.kt`**: Safely patched `handleScanResult` to *also* parse the iOS 16-byte Service UUID workaround without breaking existing Android Manufacturer Data logic.

## 2. Local Installation Commands
If you manage to get access to a Mac in the future, run these commands:
```bash
npm install
cd ios
pod install
cd ..
npx react-native run-ios --device "Your iPhone Name"
```

## 3. Cloud Build (Windows Users)
Since this is a **Bare React Native CLI** project (not Expo), you cannot use EAS easily without migrating. Instead, you must use **GitHub Actions**.

However, to create an `.ipa` that installs on a real iPhone, you **must** have an Apple Developer account to provide a Provisioning Profile and Distribution Certificate. 

If you just want to build an **unsigned** `.app` bundle for use in a cloud Simulator (like Appetize.io) or for advanced jailbreak/sideloading setups, you can add a `.github/workflows/ios.yml` with the following:
```yaml
name: iOS Build
on: [push]
jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with: { node-version: '22' }
      - run: npm install
      - run: cd ios && pod install
      - run: xcodebuild -workspace ios/AttendanceApp.xcworkspace -scheme AttendanceApp -configuration Release -sdk iphoneos CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""
```

## 4. How to Test BLE on Two Real iPhones
You cannot test BLE inside an iOS Simulator. You **must** sideload the app onto physical iPhones.
1. Download a sideloading tool like **AltStore** or **Sideloadly** on your Windows PC.
2. Obtain the compiled `.ipa` file (via GitHub Actions if you inject a free Apple ID, or by compiling on a friend's Mac).
3. Connect the iPhones via USB, open AltStore, sign in with your standard Apple ID, and push the `.ipa` to the devices.
4. Go to iPhone Settings -> General -> VPN & Device Management -> Trust your Apple ID.

## 5. Cross-Platform Test Matrix
The custom protocol ensures full bidirectional compatibility:
- **Android Faculty + Android Student**: ✅ Works natively via Manufacturer Data (0xFFFF).
- **iPhone Faculty + iPhone Student**: ✅ Works via custom iOS Service UUID (0x0000FFFF...).
- **Android Faculty + iPhone Student**: ✅ Works. Android `handleScanResult` intercepts the iOS Service UUID.
- **iPhone Faculty + Android Student**: ✅ Works. iOS `CBCentralManager` reads the Android Manufacturer Data.

## 6. Troubleshooting
- **Bluetooth Off/Permission Denied**: The app will fail safely and log an error. You must manually grant Bluetooth permissions in Settings.
- **iOS Scanning Finds No Students**: Ensure both apps are in the **Foreground**. Apple severely restricts background BLE scanning and advertising. Keep the screen on.
- **Cloud Build Fails**: Xcode updates break React Native frequently. Ensure `pod install` finishes successfully.

## 7. Honest Limitations & Security
- **Physical Identity**: iOS absolutely **does not** expose the physical hardware MAC address of devices due to privacy laws. We use `CBPeripheral.identifier` (a rotating UUID generated by iOS) as the `deviceAddress`. 
- **Anti-Proxy Reality**: If a student uninstalls and reinstalls the app, their `CBPeripheral.identifier` changes. This means the anti-proxy map is a strong deterrent, but not mathematically flawless against dedicated sabotage.
- **App Store Publishing**: Sideloaded apps expire every 7 days unless you pay $99/year for an Apple Developer Account.
